# NovelCompose 完整文档

> 这是根 README 的详细版：功能清单、使用指南、页面导览、项目结构、技术架构、配置说明、测试与 FAQ。

## 一、核心功能

| 功能 | 说明 |
|---|---|
| **双模式对话页** | 一个页面两种模式：**对话模式**（与 AI 闲聊/问设定）+ **创作模式**（流式写正文），历史各自独立 |
| **交互式创作** | 像聊天一样创作：日常问答不触发生成，**明确说"创作第几章/下一章"才写正文**；流式输出、可中断、可抽卡（一次生成多个候选供挑选）、人审/润色/重写/提交 |
| **26 智能体章节流水线** | 世界状态机 → 意图分发 → 大纲导演（全权管伏笔）→ 骨架写手 → **五科写手并行**（动作/对话/内心/描写/过渡）→ 分镜整合 → AI 味检测 → 人审；4 类网关编排、脚本节点带锁串行、断点可续跑、全程可取消 |
| **三视角审校** | 读者 / 专业 / 编辑三个视角并行独立打分，输出问题清单；不通过时触发 AI 对抗性讨论 |
| **AI 率检测（本地免费）** | 规则层 + 统计层 + **本地深度模型**三层融合判定（30%/20%/50% 加权），模型未就绪自动降级；给出具体问题与改法，30% 以内达标；离线可用、零额外成本 |
| **事实级校验** | 写完每章自动提取本章事实与事件流对账（TruthEvent 因果链），输出矛盾清单，拦"角色眼睛颜色变了"这类小错 |
| **设定库** | 15 类资产全结构化：角色 / 势力 / 怪物 / 副本 / 世界设定 / 伏笔 / 红线 / 梗 / 地点 / 情感弧线 / 爽点 / 记忆精炼 / 命名覆盖 / 事件流 / 导入 |
| **标签 + 权重** | 对标 NovelAI Lorebook：正文关键词命中标签 → 100% 注入该标签设定，同标签内按权重降序；高权重伏笔（P0）常驻不衰减；标签命中不到回退向量语义检索兜底 |
| **叙事线** | 明线/暗线 × 主线/支线管理，写作时注入"当前线推进到哪、本章该推什么"，正文提交自动回写 |
| **大纲系统** | 卷纲 → 近纲 → 章纲 三级大纲，支持 AI 生成、人工编辑 |
| **内容图谱** | 人物关系 / 势力关系 / 伏笔网络 / 章节脉络 / 世界地图 五类图谱，点节点看详情 |
| **圆桌会议** | 多个 AI 角色围坐讨论剧情走向（席位可配、可暂停/恢复/插话），结论自动写回设定库 |
| **自定义工作流** | 可视化编排生成流程（节点拖拽连线：agent / 脚本 / 网关 / 起止），内置 build / story-plan / mvp / outline / character / polish / post-hoc 等工作流 |
| **风格蒸馏** | 导入参考作品，AI 按 **19 个维度**（风格/语言/结构/叙事引擎/信息控制/人物塑造/情感算法/人味指纹…）多轮蒸馏出 skill；支持**拆书**（EPUB/PDF/DOCX/TXT 逐章提炼）、多 skill **融合**、**盲评**对比 |
| **提交后闭环** | 伏笔自动埋设、红线检测、命名归一化（别名回写正名）、审校结论回写设定库、圆桌结论落库，五子项各自容错不阻塞 |
| **记忆系统** | 每章常驻上下文 + 向量语义检索（Chroma）+ 全文精确回溯 + 分层摘要树，长篇小说不忘前情 |
| **多端运行** | 浏览器（开发/局域网）、Electron 桌面安装包、安卓（Capacitor 壳 + 竖屏适配） |

## 二、使用指南（从建项目到写完一本书）

### 1. 创建项目
打开首页 → 左上角「选择作品」→ 新建项目 → 填标题 / 题材 / 简介 / 风格。没有项目时首页会引导你创建。题材可选模板（内置 15 个题材模板）。

### 2. 搭框架
- **规划页**：让 AI 生成卷级规划（可选，长篇小说建议做）
- **大纲页**：卷大纲 → 每卷细纲 → 每章章纲。大纲质量决定正文质量，建议每级都人工看一眼、不满意就重新生成

### 3. 开始写
- **对话页（默认首页）**：切到创作模式，说"创作第一章"或"下一章"，AI 流式写正文并自动走审校。要对比多个写法？开**抽卡**一次生成几个候选。审校后弹窗出现：**通过 / 驳回重写 / 再润色**。
- **写作页**：26 智能体流水线整章产出（进度面板可见），也可人工精修章节正文（多标签、自动保存）。

### 4. 让 AI 越写越合口味
- **设置 → 蒸馏技能**：导入参考作品提炼风格 skill；上传一本书做**拆书**生成技法技能；还可把多个 skill **融合**成"九合一"。
- 生成时 skill 自动注入，相关技法按需加载（语义搜索），不浪费上下文。

### 5. 管理设定
在**设定库页**维护 15 类资产（角色/世界设定/伏笔/势力/怪物/副本/红线/梗/地点/情感弧线/爽点/记忆精炼/命名覆盖/事件流/导入），支持**标签 + 权重**；**叙事线页**管明线暗线；**百科页**全局浏览；**图谱页**看关系网；**时间线页**回看事件流。正文提交时 AI 会自动把新事实写回设定库。

### 6. 看结果
**仪表盘**看进度、**统计页**看字数与一致性、**摘要页**看章节摘要、**导出页**导出全书正文。

## 五、技术架构

### 两条创作路径，共享一个设定底座

```
路径 A · 交互式创作（灵感型）：对话 → 说"创作第X章" → 流式正文 → 审校 → 人审 → 提交
路径 B · 26 智能体流水线（量产型）：build(世界) → story-plan(故事) → mvp(章节生产) → post-hoc(后验)
两者共用：设定库(15类+标签权重) · 叙事线 · 记忆 · 质量闸门
```

### 26 智能体章节流水线（mvp）

```
world 状态机 → 意图分发 → 大纲导演(伏笔埋1收2) → 骨架写手
→ 五科写手并行（动作 / 对话 / 内心 / 描写 / 过渡）
→ 分镜整合 → AI 味检测 → 人审 → 提交后闭环(埋设/红线/归一化/回写)
```

- 4 类网关（并行/汇聚/条件/循环）编排节点；脚本节点进程级锁串行防并发污染
- 写审分离、审校三视角并行（并行网关）；非关键节点失败自动跳过，关键节点失败终止；全程可取消、断点可续跑

### AI 率检测（三层融合）

```
规则层（词/句/段级 AI 味模式）30% + 统计层（7 个分布信号）20% + 本地深度模型 50%
模型未就绪时自动降级为 规则60%+统计40%，不阻塞调用
```

### 数据存储

| 数据 | 位置 | 说明 |
|---|---|---|
| 设定库 | `project_data/bible.db` | SQLite（WAL）：15 类资产 / 叙事线 / 事件流 / 事实校验 |
| 章节正文 | `project_data/projects/{id}/` | Markdown + 工作流缓存（骨架/写手产出/世界状态） |
| Skills | `project_data/skills/*.json` | 技能库（含语义索引） |
| 蒸馏数据 | `project_data/distillation.db` | 作品/片段/轮次/Skill/融合方案 |
| 向量库 | `project_data/chroma/` | 记忆检索 + skill 语义搜索 + 题材语料 RAG |
| 配置与密钥 | `config.yaml` + `.env` | 模型与密钥（`.env` 永不进 git） |

### 模型分配（全部可自定义）

> **本平台不绑定任何特定模型/供应商（BYOK）**。所有角色默认共用主模型，你可随时在「设置 → 模型管理」添加任意 OpenAI 兼容供应商，并在「设置 → Agent 定义」为每个角色单独分配不同模型。以下仅为**角色划分与职责**，具体用哪家模型由你决定。

| 角色 | 职责 | 说明 |
|---|---|---|
| writer / polisher | 正文生成 / 润色改写 | 可与审校用不同模型（写审分离） |
| auditor / debater | 三视角审校 / 对抗讨论 | 建议与写手分开 |
| planner / architect / outliner / director | 规划 / 大纲 / 导演 | 可复用主模型 |
| summarizer / observer | 摘要 / 世界状态机 | 可复用主模型 |
| embedding | 向量检索 | 优先方舟 embedding API，未配置自动降级本地模型或关键词 |

## 六、配置说明

`config.yaml` 主要段落：

- `llm`：主模型（base_url / api_key / model / max_tokens / timeout…）
- `auditor_llm`：审校独立模型（写审分离；留空回退主模型）
- `agent_llm`：各 Agent 的模型分配（api_key 留空自动回退主模型 key）
- `embedding`：向量模型配置（未配置时自动降级）
- `content_redline_enabled`：内容题材红线开关（默认放开；设定级红线永远生效，不受开关影响）
- `project_data_dir`：项目数据目录（可自定义；打包版默认 `%APPDATA%\NovelCompose\project_data`）
- `enable_genre_rag`：题材向量语料 RAG 开关
- `allow_auto_expand_chapter`：章纲内容不足时允许 AI 自动扩充剧情

> API Key 只放 `.env`，`config.yaml` 用 `${VAR}` 占位符引用，避免密钥进 git。还支持 `NOVEL_*` 环境变量覆盖。

## 八、常见问题（FAQ）

**Q：页面打不开？**
A：确认后端 8000 与前端 5173 都已启动；页面一直转圈时看后端日志是否有报错。

**Q：生成很慢或失败？**
A：多为模型服务限流/超时。检查 `.env` 密钥是否有效、`config.yaml` 模型名是否正确；长文本生成可达数分钟，请耐心等流式输出（界面有停止按钮可中断）。

**Q：我想换一家模型用？**
A：完全支持（BYOK）。在「设置 → 模型管理」添加新的 OpenAI 兼容供应商，再在「Agent 定义」里给对应角色分配即可；留空自动回退主模型。

**Q：skill 语义搜索没效果？**
A：语义搜索需要配置 embedding API。未配置时自动降级为关键词搜索，不影响使用。

**Q：数据存在哪？**
A：由 `config.yaml` 的 `project_data_dir` 决定（打包版默认 `%APPDATA%\NovelCompose\project_data`）。整个目录拷贝即可备份/迁移。

**Q：手机上怎么用？**
A：方式一：手机与电脑同 Wi-Fi，浏览器访问 `http://电脑IP:8000`；方式二：`npm run app:build` + Android Studio 打包 APK 安装。

**Q：写了一半想换题材？**
A：新建项目即可；设定库、大纲、章节、断点都按项目隔离，互不影响。

**Q：AI 率检测要额外付费吗？**
A：不用。内置本地深度模型，离线可跑、零额外成本。
