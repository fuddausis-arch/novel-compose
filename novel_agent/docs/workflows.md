# NovelCompose 工作流文档

NovelCompose 提供 7 条工作流，覆盖从建书到后验裁决的完整小说生成生命周期。

## 工作流总览

| 工作流 | 名称 | 阶段 | 资源边界 | 运行前置 |
|--------|------|------|----------|----------|
| build | 建书工作流 | 立项 | 1-2 次 LLM 调用 | 无 |
| character | 角色工作流 | 设定 | 3-5 次 LLM 调用 | 项目已创建 |
| story-plan | 故事规划工作流 | 规划 | 2-4 次 LLM 调用 | 项目已创建 + 有角色 |
| outline | 大纲工作流 | 规划 | 1-3 次 LLM 调用/章 | story-plan 完成 |
| mvp | 正文生成工作流 | 生成 | 5-15 次 LLM 调用/章 | 有章纲 |
| polish | 润色工作流 | 优化 | 2-5 次 LLM 调用/章 | 有已生成正文 |
| post-hoc | 后验裁决工作流 | 质检 | 1-2 次 LLM 调用/章 | 有已保存摘要 |

---

## 1. build（建书工作流）

### 阶段说明
创建项目 + 初始化世界观 + 生成题材模板。

### 流程
1. 创建 Project 记录（标题/题材/简介/风格）
2. 加载题材模板（references/genres/ 下的对应 .md 文件）
3. 初始化基本世界观设定
4. 生成项目配置目录

### 资源边界
- 1-2 次 LLM 调用（生成世界观摘要）
- 1 次数据库写入（创建 Project）

### 运行前置
- 无（项目第一步）

---

## 2. character（角色工作流）

### 阶段说明
批量创建角色 + 建立关系网 + 生成角色弧光。

### 流程
1. 根据题材和故事大纲，生成角色清单（主角/配角/反派）
2. 为每个角色生成详细设定（性格/动机/背景/绝对禁忌）
3. 建立角色关系网（盟友/敌人/师徒等）
4. 生成角色弧光（成长轨迹）

### 资源边界
- 3-5 次 LLM 调用（角色生成 + 关系网 + 弧光）
- N 次数据库写入（N = 角色数）

### 运行前置
- 项目已创建（build 完成）
- 建议有基本世界观设定

---

## 3. story-plan（故事规划工作流）

### 阶段说明
生成卷/arc/章纲的分层大纲。

### 流程
1. 根据题材和角色，规划全书卷结构（每卷主题/高潮/字数预算）
2. 为每卷生成 arc（故事弧线）
3. 为每个 arc 生成章节列表（标题/概要/阶段）
4. 标记黄金三章（前3章）和上架章

### 资源边界
- 2-4 次 LLM 调用（卷规划 + arc 规划 + 章节列表）
- 数据库写入（大纲表）

### 运行前置
- 项目已创建（build 完成）
- 建议有角色设定（character 完成）

---

## 4. outline（大纲工作流）

### 阶段说明
生成详细章纲（爽点/伏笔/角色约束）。

### 流程
1. 读取 story-plan 产出的章节列表
2. 为每章生成详细章纲：
   - required_beats：爽点清单（tier/type/intensity）
   - required_hooks：章末钩子（类型/强度）
   - owed_debts：欠账（背景压力）
   - character_constraints：角色状态约束
   - narrative_function：叙事意图（情感弧线/节奏意图/主题推进）
3. 标记应埋/应回收的伏笔

### 资源边界
- 1-3 次 LLM 调用/章
- 数据库写入（大纲表 + 伏笔表）

### 运行前置
- story-plan 完成（有章节列表）
- 建议有角色设定（用于角色约束）

---

## 5. mvp（正文生成工作流）

### 阶段说明
写正文 + 审计 + 润色 + 摘要 + 后验裁决。

### 流程
1. **world_engine**：写前世界推演（势力动态/暗线/世界事件）
2. **assemble**：装配章节上下文（core memory + archival + 题材模板 + CSV 参考资料）
3. **context_trimmer**：上下文裁剪（控制 token 预算）
4. **analyze_style**：分析人类网文样本写法特征
5. **write**：调 LLM 生成章节正文
6. **audit**：独立审校（三视角并行 + 对抗讨论 + 确定性检查）
7. **human_review**：人审 checkpoint（可选，高置信度跳过）
8. **style_refine**：风格模仿润色（学习人类作家写法）
9. **save_text**：保存正文到文件
10. **summarize**：校验正文满足大纲约束 + 摘要 + 伏笔回收
11. **post_hoc**：后验裁决（世界事实一致性检查）

### 写审循环
- 审计不通过 -> rewrite -> audit（最多 4 轮）
- 连续 2 轮 score 无改善 -> 降级接受最高分草稿
- 人审 reject -> rewrite（注入用户意见）

### 资源边界
- 5-15 次 LLM 调用/章（含重写循环）
- 字数硬上限：3500 字（从 节奏阈值.csv 读取）
- 超时保护：35 分钟

### 运行前置
- **必须有章纲**（outline 完成）
- 建议有角色设定（用于角色一致性检查）
- 建议有伏笔规划（用于伏笔埋设/回收检查）

---

## 6. polish（润色工作流）

### 阶段说明
对已有正文做深度去 AI 味 + 风格模仿。

### 流程
1. 加载已生成的章节正文
2. LLM 润色（清除 AI 痕迹词 + 标点修复 + 段落节奏调整）
3. 规则后处理（感叹号降级 + 排比打断 + 重复截断）
4. oh-story 7 Gate 多轮深度净化（去 AI 味）
5. 字数/限频词/伏笔关键词校验

### 资源边界
- 2-5 次 LLM 调用/章（润色 + 格式修复 + deslop）
- deslop 最大 Pass 数可配置

### 运行前置
- 有已生成正文（mvp 完成）
- 正文已保存到文件

---

## 7. post-hoc（后验裁决工作流）

### 阶段说明
对已保存章节做事后一致性检查。

### 流程
1. observer：读取已保存章节的摘要 + 正文片段
2. 检查世界事实一致性（角色位置/状态/势力动态/世界事件）
3. arbiter：裁决是否有关键冲突
4. critical 级冲突 -> 触发定向返工（reject_upstream 机制）

### 资源边界
- 1-2 次 LLM 调用/章（observer + arbiter）
- 返工循环上限：3 次

### 运行前置
- 有已保存摘要（summarize 完成）
- 建议有完整世界状态记录

---

## 章节循环顺序

连续写多章时，每章的执行顺序：

```
mvp -> polish(可选) -> post-hoc -> 下一章
```

- **mvp**：必须执行，生成正文
- **polish**：可选，对质量要求高的章节执行深度润色
- **post-hoc**：推荐执行，检查跨章一致性
- 一章完成后，自动进入下一章的 mvp

## 工作流选择决策

参见 `novel_agent/skills/writing_assistant.py` 的 `select_workflow()` 函数。

决策树：
1. 无项目 -> build
2. 无世界观 -> build
3. 无角色 -> character
4. 无大纲 -> story-plan
5. 有大纲无章节 -> mvp
6. 有章节无摘要 -> post-hoc
7. 一切就绪 -> mvp（继续写下一章）
